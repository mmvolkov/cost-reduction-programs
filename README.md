# Программы снижения затрат

Русскоязычный открытый практикум для собственников и финансовых директоров: библиотека мер, учебные кейсы, интерактивный финансовый расчёт и AI-ассистент. Визуальное направление вдохновлено проектом владельца [Scout «Аргумент»](https://scout-argument.ru/).

## Что внутри

- 6 отраслевых профилей с типовыми направлениями и контрольными метриками.
- 9 мер в закупках, операциях, IT, управлении запасами. У каждой есть действия, метрика и ограничение по качеству/рискам.
- 3 оригинальных **условных**, а не клиентских кейса. Каждый переносится в калькулятор.
- Расчёт первого года, устойчивого годового эффекта, окупаемости и накопленного результата. Линейный разгон, разовые и регулярные затраты учитываются отдельно.
- Скачивание расчёта и плана 30/60/90 в TXT, HTML, PDF и DOCX. Все форматы строятся из одного проверенного набора данных в браузере.
- Два сценария AI: свободный диалог или разбор выбранных мер и текущего расчёта.
- Шестерёнка: выбор разрешённого администратором профиля модели, вариативности и кода доступа. Это намеренно не публичный редактор endpoint/API key.
- Контекстный AI рабочей программы: одна мера и задача, точный предпросмотр, отдельное согласие, проверка устаревшего ответа и подтверждение применения только выбранного текстового поля. Финансы и факты AI не изменяет.
- 9 дополнительных учебных пилотов с условиями применимости, данными, шагами, метриками и условиями остановки. Это не результаты реальных клиентов; суммы не подставляются автоматически.
- Локальные участники, комментарии, история и решения по версии программы передаются в JSON. Имя и роль вводятся вручную, личность не проверяется. Это не контроль доступа, электронная подпись или серверная синхронизация. Импорт создает независимую копию, а не слияние; полученные решения требуют перепроверки и не подтверждают экономию.
- Отчет для согласования содержит запрос решения, ограничения данных, риски и ответственных во всех четырех форматах. Общего серверного пространства, регистрации и приглашений нет.
- Адаптивная вёрстка, клавиатурная навигация, нативные диалоги, отсутствие внешних шрифтов, аналитики и cookies; установка npm-зависимостей для запуска не требуется.

## Запуск

Требуется Node.js 22.9+ (рекомендуется актуальный Node.js 24 LTS).

```bash
cp .env.example .env
npm start
```

Открыть `http://127.0.0.1:3000`. Установка npm-пакетов не требуется. Без серверного ключа и инициализированного устойчивого счётчика контент и калькулятор работают, AI показывает статус «не подключён». Закрытый режим также требует код доступа.

Для разработки: `npm run dev`. Этот режим читает переменные процесса; `npm start` дополнительно загружает локальный `.env`.

## Подключение AI

Полная инструкция: [docs/AI-SETUP.md](docs/AI-SETUP.md).

По умолчанию настроен серверный профиль:

- endpoint: `https://api.ai-assistants.softline.com/v1`
- название в интерфейсе: `Local`
- модель: `qwen3.8-27b-nvfp4`
- секрет: переменная окружения `AI_API_KEY`

По умолчанию нужен непубличный `AI_ACCESS_CODE`. Публичный режим включается только явно через `AI_ACCESS_MODE=public`, требует HTTPS origin и тот же устойчивый счётчик. Не используйте ключ API вместо кода доступа. Никогда не добавляйте ключи в `public/`, GitHub repository variables, README, браузер или URL. `.env` исключён из Git. Для настоящего запуска внесите секрет через secret manager вашей платформы.

Никакие реальные ключи не включены. Внешний endpoint и наличие модели следует проверить при настройке: автоматические тесты используют подставной OpenAI-совместимый сервис и не расходуют платные запросы.

## Экспорт отчёта

В калькуляторе выберите TXT, HTML, PDF или DOCX и нажмите «Скачать отчёт». Перед экспортом все пять полей проверяются, а результат пересчитывается тем же детерминированным калькулятором. Во всех форматах одинаковые исходные данные, результаты, выбранные меры, план 30/60/90, двенадцать месячных значений и ограничения методики. Свободная AI-переписка в отчёт не включается.

Файлы формируются локально в браузере, без загрузки содержимого на сервер или в сторонний сервис. PDF содержит встроенный кириллический шрифт; DOCX является редактируемым документом Word, а не HTML с измененным расширением. Тяжелые компоненты PDF загружаются с этого же сайта только при выборе формата. TXT сохраняется в UTF-8 с BOM, HTML является автономным файлом.

Название модели `Local` является отображаемым именем профиля. Адрес провайдера не меняется: AI-сообщения по-прежнему передаются настроенному серверному провайдеру после согласия пользователя. Экспорт не обращается к модели и не расходует бюджет AI.

## Проверки и GitHub Actions runner

```bash
npm run check
```

Команда выполняет проверку синтаксиса и unit/API/security tests через встроенный `node:test`.

`.github/workflows/ci.yml` использует **GitHub-hosted runner `ubuntu-latest`** и проверяет Node.js 22/24 на push, pull request и ручном запуске. Секрет модели не требуется. Это CI-проверка, а не постоянный сервер и не автоматическая публикация сайта. Self-hosted runner не настраивается.

Успешный запуск workflow подтверждается отдельно для конкретного commit на вкладке Actions.

## Публикация

Для AI нужен сервер Node.js. Обычный GitHub Pages обслуживает только статические файлы и не может безопасно хранить ключ и проксировать модель. Разместите приложение на сервере/платформе с Node.js и HTTPS reverse proxy, установите `PUBLIC_ORIGIN` и секреты. Конкретный хостинг и домен не настроены этим проектом.

Пример production-настроек, reverse proxy и ограничения защиты описаны в [docs/AI-SETUP.md](docs/AI-SETUP.md). Для публичного AI реализованы общий устойчивый бюджет до 100 попыток/сутки UTC, 2 параллельных запроса и максимум 1000 completion tokens. Все процессы должны использовать один локальный том со счётчиком. Несколько хостов требуют централизованного бюджета. Финансового потолка это не задаёт: настройте денежные квоты у провайдера. Не публикуйте общий код доступа на странице.

## Как считается экономия

Денежные поля — **млн ₽**. База — только расходы, на которые влияет программа, а не вся выручка компании.

1. Годовая валовая экономия на полном ходу = база × процент снижения.
2. Месячная экономия = годовая / 12 × коэффициент разгона. При разгоне M месяцев коэффициент месяца k = min(1, (k − 0,5) / M); при M = 0 коэффициент равен 1.
3. Первый год = сумма 12 месячных экономий − 12 × поддержка − разовые затраты.
4. Устойчивый чистый эффект = годовая валовая экономия − 12 × поддержка.
5. Окупаемость — пересечение нуля накопленным эффектом с линейной интерполяцией внутри месяца. Горизонт поиска 120 месяцев.

Осторожный сценарий уменьшает исходное предположение об экономии до 60%, округляя к ближайшим 0,5 процентного пункта. Это sensitivity check, не вероятность и не отраслевой норматив.

Не моделируются налоги, сезонность, изменение объёмов/цен, дисконтирование, стоимость капитала и потеря маржи. При возможном ущербе выручке скорректируйте сценарий отдельно. Возврат денег из запасов и высвобождение рабочего времени **не равны** регулярной денежной экономии. Эффекты мер не складываются автоматически, чтобы не провоцировать двойной счёт.

## Содержание и источники

Тексты и числовые сценарии подготовлены самостоятельно. Отраслевые направления сверены с материалом [«Системы Финансовый директор»](https://fin.action360.ru/#/document/16/44629/) через разрешённый доступ. Защищённый текст, таблицы и скачиваемые документы источника не воспроизводятся. Доступ к оригиналу может требовать подписки.

Числа в кейсах — учебные допущения. Здесь нет заявлений о результатах реальных клиентов, гарантий экономии или партнёрства с источником.

## Структура

- `public/` — страница, стили, сценарии, библиотека мер и чистая функция расчёта.
- `server.mjs` — статический сервер и AI proxy.
- `lib/server-security.mjs` — валидация, профили, общий flood limiter и заголовки.
- `lib/ai-budget.mjs` — устойчивый общий дневной бюджет и параллельные слоты.
- `scripts/init-ai-budget.mjs` — одноразовая ручная инициализация счётчика, не часть каждого deploy.
- `test/` — финансовые и API/security tests.
- `docs/AI-SETUP.md` — настройка и production-ограничения.

## GitHub Pages и серверная копия

Workflow `pages.yml` проверяет код и публикует **только public/** после push/merge в main. Секреты, сервер и .env в Pages artifact не входят. До подключения backend это честно обозначенная статическая демонстрация: материалы, калькулятор и экспорт работают, AI отключен.

После проверенного запуска backend администратор задает GitHub repository variable `PUBLIC_API_BASE_URL=https://scout-argument.ru/cost-reduction-programs/api/` и повторно запускает Pages. Это публичный адрес, не секрет. Для backend нужны `BASE_PATH=/cost-reduction-programs`, `PUBLIC_ORIGIN=https://scout-argument.ru`, `CORS_ALLOWED_ORIGINS=https://mmvolkov.github.io`. CORS разрешает только этот точный origin, не wildcard. Режим доступа задаётся на сервере: в закрытом режиме требуется код, в явно включённом публичном режиме действуют общий устойчивый бюджет и ограничения запросов.

Статус серверного развертывания и безопасная схема: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Наличие workflow Pages не означает, что серверная копия развернута.

## Рабочие программы P1

Новый раздел «Программы» сохраняет несколько независимых программ в этом браузере: параметры каждой меры, исполнение и месячный план-факт. Есть версии JSON для переноса и отчёты TXT/HTML/PDF/DOCX. Учебные кейсы не заменяют рабочие данные. Неполные параметры и непроверенные пересечения не выдаются за достоверный итог; финансовые результаты считает код, не AI.

[Сохранение, методика, ограничения и проверка P1](docs/PROGRAM-MANAGEMENT.md). Изменения проходят PR и полный CI (Node.js 22/24, Docker build и smoke test), затем сливаются в `main`. Успешный workflow Pages публикует статическую версию; сервер Scout обновляется отдельно по [инструкции развертывания](docs/DEPLOYMENT.md).

## P2 Локальные инструменты проверки программы

Ветка `codex/program-management-p2` добавляет пошаговую диагностику без AI, локальный импорт CSV/XLSX с проверкой строк и дубликатов, сравнение базовой программы с независимыми альтернативами и прозрачную приоритизацию мер. Сохранения P1 мигрируют в схему 2 с сохранением фактов. Все расходы остаются в браузере; применение базы не создает факт экономии. Методика, ограничения и миграция описаны в [руководстве](docs/PROGRAM-MANAGEMENT.md).

Новые DOCX используют A4, поля 36 pt и Calibri 11. Представление отчетов нормализует е/Е и дефис U+002D; исходные поля и JSON не переписываются. PR P2 не сливается до завершения независимой проверки, серверная публикация остается отдельной.

## P3 Контекст, учебные пилоты и локальное согласование

Контекстный AI обсуждает одну выбранную меру только после предпросмотра передаваемых сведений и отдельного согласия. Полученный текст можно применить в разрешенное текстовое поле после сравнения и подтверждения; модель не меняет финансовые параметры и факты. Изменение программы или конфликт другой вкладки блокирует устаревший черновик.

Девять учебных пилотов можно читать, копировать и после отдельного предпросмотра переносить в заметки существующей меры, не меняя ее экономику. Участники, комментарии, история и решения хранятся локально и передаются независимым JSON-файлом v3. Имена и роли введены вручную: это не авторизация, электронная подпись или серверная синхронизация. Решение связано с версией содержания и не подтверждает экономию. История группирует последовательный ввод одного поля, сохраняя немедленное устаревание прежнего решения.

P3 проходит отдельный draft PR и CI Node 22/24 + Docker; слияние требует завершения независимой приемки. Main и сервер не обновляются публикацией этой ветки. [Методика и ограничения](docs/PROGRAM-MANAGEMENT.md), [границы локального согласования](docs/P3-COLLABORATION-ARCHITECTURE.md).
