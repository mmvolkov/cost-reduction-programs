# Два адреса одного проекта

## GitHub Pages

- Источник: GitHub Actions.
- После изменений main запускается проверка и публикация `public/`.
- До включения PUBLIC_API_BASE_URL AI явно отключен; статические функции доступны.
- Никогда не подставлять секрет модели в статическую сборку: Secrets защищают хранение, но не делают секретом значение, записанное в JavaScript.

## Действующий сервер Scout

- Публичный раздел: https://scout-argument.ru/cost-reduction-programs/.
- Статическая версия Pages: https://mmvolkov.github.io/cost-reduction-programs/.
- Рабочий checkout сервера: `/home/scoutadmin/cost-reduction-programs`.
- Compose-проект: `cost-reduction-programs`, сервис: `cost-reduction-app`.
- Traefik использует существующую external-сеть `n8n_default` и направляет только путь раздела на контейнер приложения.

Этот маршрут подтверждён предыдущей серверной проверкой, а не новой проверкой файловой системы в ходе подготовки P1. Перед каждым обновлением исполнитель проверяет текущий checkout и контейнер: описание маршрута само по себе не подтверждает, что конкретный релиз уже развёрнут.

GitHub Actions публикует Pages, но не подключается к серверу. Серверное обновление выполняется отдельно через доверенную сессию локального Codex/администратора. Не передавайте SSH-ключи, пароли или содержимое `.env` в чат, репозиторий и журналы.

## Docker-развертывание

В репозитории есть Dockerfile, compose.yaml и изолированный smoke test. Образ Node 24 собирается с проверкой тестов; runtime работает uid 1000, без root, дополнительных capabilities, публикации host-портов и Docker socket. В образ не попадают .env, Git-история, тесты или документы. Корневая файловая система read-only, отдельный named volume /app/state хранит устойчивый счётчик AI. Память ограничена 256 МБ, CPU 0.5, процессы 128.

Compose подключается только к уже существующей external-сети n8n_default. Он не создает или перенастраивает сеть, Traefik или основной Scout. Маршрут: Host scout-argument.ru И точный /cost-reduction-programs либо префикс /cost-reduction-programs/. Priority 100 выше существующего общего маршрута 20. Остальные пути и домены не перехватываются. TLS использует существующий resolver mytlschallenge. Это становится публичным маршрутом только после явного запуска контейнера.

Приложение принимает исходный путь через BASE_PATH; StripPrefix не используется. Перед первым запуском проверьте существующий proxy, свободные ресурсы и отсутствие конфликтующего сервиса/маршрута.

### Обновление существующей установки

Сначала проверьте PR и полный CI для предназначенного к выпуску commit. Выполняйте следующие шаги в существующей доверенной серверной сессии, по одному, останавливаясь при любой ошибке. Они обновляют только `cost-reduction-app`, не основной Scout и не соседние сервисы.

1. Перейдите в существующий checkout и проверьте чистоту и ветку:

   ```sh
   cd /home/scoutadmin/cost-reduction-programs
   git status --short
   git branch --show-current
   git rev-parse HEAD
   ```

   Ожидается чистый checkout на `main`. При локальных изменениях или другой ветке остановитесь: не применяйте reset/clean и не затирайте чужую работу. До сборки сохраните текущие SHA и ID образа для возможного отката, не выводя окружение контейнера:

   ```sh
   docker compose images -q cost-reduction-app
   ```

2. Обновите только fast-forward и сверьте SHA с опубликованным результатом PR:

   ```sh
   git pull --ff-only
   git rev-parse HEAD
   ```

   Если SHA отличается от проверенного релиза, сначала выясните причину и проверьте его CI.

3. Проверьте конфигурацию без вывода значений и соберите образ только этого сервиса:

   ```sh
   docker compose config --quiet
   docker compose build cost-reduction-app
   ```

   Сборка запускает тесты и не останавливает действующий контейнер. Не продолжайте при ошибке. **Обычный `docker compose config` может раскрыть секреты; используйте только `--quiet`.**

4. Только после успешной сборки обновите контейнер из локального образа, без повторной сборки, pull и зависимостей:

   ```sh
   docker compose up -d --no-deps --no-build --pull never cost-reduction-app
   ```

   Возможен краткий перерыв именно этого раздела при пересоздании контейнера. Существующие `.env` и named volume `ai-budget-state` сохраняются. Не создавайте `.env` заново, не запускайте инициализацию бюджета при обычном обновлении и не выполняйте `down -v`, удаление тома или сети.

5. Проверьте сервис, health и оба сайта:

   ```sh
   docker compose ps cost-reduction-app
   curl --fail --silent --show-error https://scout-argument.ru/cost-reduction-programs/api/health
   curl --fail --silent --show-error --output /dev/null https://scout-argument.ru/
   ```

   Дождитесь healthy, затем проверьте интерфейс раздела, новые файлы релиза и существующий калькулятор. Программы P1 хранятся в браузере отдельно для каждого origin; они не переносятся между Pages и Scout автоматически. Не проверяйте секреты через `docker inspect` с выводом environment.

Для отката используйте сохранённые SHA и образ только этого сервиса; не откатывайте `.env` или бюджетный том. Не применяйте команды к каталогу основного Scout. Остановка `docker compose stop cost-reduction-app` прекращает доступность раздела и сама по себе не является откатом.

GitHub CI проверяет Compose, Docker build и smoke test без секретов, production-сети и публикации образа. Этот job **не выполняет серверный deployment**. Создание SSH/deployment credentials и автоматического серверного workflow не входит в обычное обновление.

## AI: сохранение настроек и первая активация

Обычное обновление P1 сохраняет действующие настройки AI, T=0, endpoint, ключи и счётчик. Следующие шаги относятся только к первой активации AI на новой установке, а не к каждому deploy. Сверяйте их с текущим сервером, не выполняйте пакетно без проверки:

1. Сохраните текущий commit/image и проверьте Compose через `docker compose config --quiet`. Не публикуйте обычный config с секретами.
2. До включения AI один раз инициализируйте persistent budget по [AI-SETUP.md](AI-SETUP.md). Повторные deploy используют тот же named volume; удаление/сброс запрещены как способ восстановления лимита.
3. Через закрытую серверную сессию задайте API key и осознанно выберите `AI_ACCESS_MODE=public`; публичный режим не требует пользовательского кода. Сохраните PUBLIC_ORIGIN и CORS только для нужных адресов.
4. После отдельного подтверждения выполните обновление только этого сервиса, затем health/config и один тестовый вопрос без бизнес-данных. `/api/config` должен показывать public, enabled:true и лимиты100/2/1000.
5. Убедитесь в сохранности основного Scout и устойчивости счётчика при последующем плановом recreate. Не удаляйте volume.

Общий лимит входящих запросов намеренно не IP-based и игнорирует forwarded headers. Дневной бюджет считает все upstream попытки, включая ошибки. Это **не денежный потолок**: до публичного живого AI задайте финансовую квоту и уведомления у провайдера. Автодеплой сервера и новые deployment credentials этим изменением не включаются.
