# Два адреса одного проекта

## GitHub Pages

- Источник: GitHub Actions.
- После изменений main запускается проверка и публикация `public/`.
- До включения PUBLIC_API_BASE_URL AI явно отключен; статические функции доступны.
- Никогда не подставлять секрет модели в статическую сборку: Secrets защищают хранение, но не делают секретом значение, записанное в JavaScript.

## Облакотека: эксплуатация проверяется отдельно

Из текущей облачной рабочей среды соединение с SSH SSH-сервером не устанавливается (`Network is unreachable`). Аутентификация не выполнялась и конфигурация production не проверена. Автодеплой на сервер не включен; нельзя безопасно угадывать reverse proxy, директории, процессы и права рядом с действующим Scout.

Первая проверка с доверенного компьютера только читает окружение:

```sh
ssh -p SSH_PORT DEPLOY_USER@SERVER_HOST 'id; hostname; command -v node; command -v docker; command -v nginx; command -v caddy; ls -ld /opt /srv /var/www'
```

Не передавайте пароли или содержимое .env в выводе.

## Docker-развертывание

В репозитории есть Dockerfile, compose.yaml и изолированный smoke test. Образ Node 24 собирается с проверкой тестов; runtime работает uid 1000, без root, дополнительных capabilities, публикации host-портов и Docker socket. В образ не попадают .env, Git-история, тесты или документы. Корневая файловая система read-only, отдельный named volume /app/state хранит устойчивый счётчик AI. Память ограничена 256 МБ, CPU 0.5, процессы 128.

Compose подключается только к уже существующей external-сети n8n_default. Он не создает или перенастраивает сеть, Traefik или основной Scout. Маршрут: Host scout-argument.ru И точный /cost-reduction-programs либо префикс /cost-reduction-programs/. Priority 100 выше существующего общего маршрута 20. Остальные пути и домены не перехватываются. TLS использует существующий resolver mytlschallenge. Это становится публичным маршрутом только после явного запуска контейнера.

Приложение принимает исходный путь через BASE_PATH; StripPrefix не используется. Перед первым запуском проверьте существующий proxy, свободные ресурсы и отсутствие конфликтующего сервиса/маршрута.

### Первый шаг после обновления кода

```sh
git -C "$HOME/cost-reduction-programs" pull --ff-only
```

Далее выполняйте по одному шагу с проверкой результата:

1. Проверить `docker compose version` (Compose v2).
2. В каталоге проекта создать .env из .env.example, не перезаписывая существующий файл, и ограничить доступ к нему. На первом запуске можно оставить AI_API_KEY и AI_ACCESS_CODE пустыми: сайт/калькулятор работают, AI отключен. Ключи не передавайте в терминальные логи.
3. `docker compose config --quiet` - синтаксическая проверка. **Не присылайте вывод обычного docker compose config: он может раскрывать .env.**
4. `docker compose build` - собирает образ и запускает тесты, не меняет маршрутизацию.
5. После согласования публичного маршрута: `docker compose up -d --no-deps cost-reduction-app`.
6. Проверить `docker compose ps`, состояние health, HTTP https://scout-argument.ru/cost-reduction-programs/api/health и сохранность основного сайта. Проверить UI, относительные asset URLs и диалог после задания секретов.

Остановка/откат только этого нового проекта: `docker compose stop cost-reduction-app`; не выполняйте команды в каталоге Scout и не удаляйте external-сеть. Сохраните предыдущий commit/image перед будущим обновлением. На первом запуске остановка нового контейнера удаляет только его Traefik-маршрут.

GitHub CI проверяет Compose, docker build и smoke test без секретов, без production-сети и без публикации образа. Этот job **не выполняет deployment**.

## Предлагаемая схема после проверки сервера

1. Отдельный каталог /srv/cost-reduction-programs, отдельный непривилегированный service user и Node 24. Приложение слушает только loopback на свободном порту.
2. Reverse proxy маршрутизирует только /cost-reduction-programs/ к этому приложению, не изменяя другие маршруты Scout. Native BASE_PATH сохраняет префикс; прокси не должен срезать его. Перед изменением - резервная копия и проверка конфигурации; после - health check и проверка основного сайта, с откатом при ошибке.
3. Секреты хранятся отдельно от релизов, с доступом только service user. API key и access code не включаются в файлы сайта, артефакты, журналы или команды shell trace.
4. Для GitHub Actions нужен отдельный ограниченный deployment credential, а не пароль с root-доступом. Ограничить его конкретным проектом/командой, закрепить SSH host key по доверенному источнику и защитить production environment. Создание учетной записи, ключей, sudo/SSH-ограничений и изменение production proxy требуют согласования.
5. После проверки создать workflow on push main: tests -> Pages + deploy production. Deploy принимает только проверенный commit и не запускается на недоверенных PR. Сериализовать deployment, сохранять предыдущий релиз, проверять /cost-reduction-programs/api/health и откатывать неудачный запуск.
6. Проверить реальный Qwen одним тестовым сообщением без бизнес-данных. Затем задать PUBLIC_API_BASE_URL для GitHub Pages и выполнить тест preflight/диалога с обоих адресов.

Привилегированные пароли не следует помещать в CI без отдельного согласования. Даже зашифрованный GitHub secret дает workflow доступ к соответствующему аккаунту; перед выдачей production-доступа нужны точные ограничения и подтверждение владельца.

## Подготовленный публичный AI: отдельная ручная активация

Обновление кода не запускает production и не задаёт живой ключ. После pull/build сверяйте инструкции с текущим сервером, не выполняйте шаги пакетно без проверки:

1. Сохраните текущий commit/image и проверьте Compose через `docker compose config --quiet`. Не публикуйте обычный config с секретами.
2. До включения AI один раз инициализируйте persistent budget по [AI-SETUP.md](AI-SETUP.md). Повторные deploy используют тот же named volume; удаление/сброс запрещены как способ восстановления лимита.
3. Через закрытую серверную сессию задайте API key и осознанно выберите `AI_ACCESS_MODE=public`; публичный режим не требует пользовательского кода. Сохраните PUBLIC_ORIGIN и CORS только для нужных адресов.
4. После отдельного подтверждения выполните обновление только этого сервиса, затем health/config и один тестовый вопрос без бизнес-данных. `/api/config` должен показывать public, enabled:true и лимиты100/2/1000.
5. Убедитесь в сохранности основного Scout и устойчивости счётчика при последующем плановом recreate. Не удаляйте volume.

Общий лимит входящих запросов намеренно не IP-based и игнорирует forwarded headers. Дневной бюджет считает все upstream попытки, включая ошибки. Это **не денежный потолок**: до публичного живого AI задайте финансовую квоту и уведомления у провайдера. Автодеплой сервера и новые deployment credentials этим изменением не включаются.
