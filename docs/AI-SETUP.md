# AI: закрытый пилот или публичный режим

Node.js 22.9+; внешних npm-зависимостей нет. Ключ находится только на сервере. Этот код сам не записывает живые секреты, не включает AI и не выполняет production deploy.

## Обязательная защита во всех режимах

AI включается только при доступном ключе провайдера и **заранее инициализированном устойчивом счётчике**. `AI_ACCESS_MODE=code` по умолчанию дополнительно требует `AI_ACCESS_CODE`. `AI_ACCESS_MODE=public` снимает запрос кода только намеренно, при наличии точного HTTPS `PUBLIC_ORIGIN`.

Жёсткие верхние пределы в коде:

- **100 обращений к модели за календарные сутки UTC на всё приложение**, суммарно по профилям и посетителям. Допустим меньший `AI_DAILY_REQUESTS`. Сброс в 00:00 UTC, не скользящие 24 часа.
- **2 одновременно выполняемых запроса**, можно уменьшить `AI_MAX_CONCURRENT`.
- В upstream передаётся **`max_tokens: 1000`** или меньший `AI_MAX_COMPLETION_TOKENS` (минимум 64). Совместимость и соблюдение параметра подтверждаются у провайдера.
- 45 секунд ожидания upstream, 48 000 байт тела запроса, до 20 сообщений, до 6 000 символов на сообщение и 24 000 суммарно.
- Дополнительная защита от частых запросов: **20 входящих POST в минуту глобально на процесс**, максимум 30 через `AI_REQUESTS_PER_MINUTE`. Считаются и отклонённые POST. Это не индивидуальный IP-лимит.

В дневной бюджет записывается **попытка до обращения к провайдеру**. Ошибки, тайм-ауты и обрывы не возвращают её: провайдер мог уже выполнить оплачиваемую работу. Поэтому успешных ответов может быть меньше 100. Невалидный запрос или отказ из-за занятых слотов до upstream не расходует дневной бюджет.

**Это не финансовый потолок.** Входные токены, внутренние/выходные токены, условия тарифа и поведение провайдера могут влиять на стоимость. Лимит запросов не гарантирует максимальную сумму в рублях или валюте. До использования живого ключа задайте доступный у провайдера денежный лимит/квоту и уведомления. Публичный доступ также позволяет посторонним намеренно исчерпать общий дневной бюджет; Origin и rate limit не являются защитой от мотивированного бота.

## Настройки

```dotenv
AI_API_KEY=
AI_ACCESS_MODE=code
AI_ACCESS_CODE=
AI_STATE_PATH=/absolute/private/directory/ai-budget.json
AI_DAILY_REQUESTS=100
AI_MAX_CONCURRENT=2
AI_MAX_COMPLETION_TOKENS=1000
AI_REQUESTS_PER_MINUTE=20
PUBLIC_ORIGIN=https://scout-argument.ru
```

Не вставляйте реальный ключ в README, Git, статическую сборку, браузер, URL, скриншот или вывод терминала. Используйте отдельный серверный secret manager либо локальный `.env` с ограниченным доступом. Код доступа — не API key. При выборе публичного режима посетителю не нужен код; согласие на передачу диалога модели остаётся обязательным.

Провайдер по умолчанию: `https://api.ai-assistants.softline.com/v1`, модель `qwen3.8-27b-nvfp4`, OpenAI-совместимый `/chat/completions`. Реальный тест выполняйте отдельным сообщением без бизнес-данных после настройки секретов.

## Одноразовая инициализация устойчивого счётчика

Счётчик **не создаётся автоматически при запуске** и не обнуляется из-за потери файла. Без файла, при повреждении, неверных правах, недоступном диске или проблеме блокировки AI закрывается с 503. Материалы и калькулятор продолжают работать. `/api/config` показывает `enabled:false`, если счётчик недоступен.

Для обычного Node-развёртывания заранее создайте отдельный каталог, доступный только пользователю сервиса, назначьте абсолютный `AI_STATE_PATH`, затем один раз выполните:

```sh
npm run ai:init
```

Команда не перезаписывает существующий файл, даже повреждённый. Повторный запуск сообщает, что файл уже существует, и завершается ненулевым кодом без изменения счётчика.

Для подготовленного Docker Compose путь зафиксирован `/app/state/ai-budget.json`; named volume `ai-budget-state` сохраняется между пересозданиями контейнера. Каталог образа принадлежит uid 1000 и имеет права 0700. После сборки образа, до включения AI, одноразовая команда:

```sh
docker compose run --rm --no-deps --label traefik.enable=false cost-reduction-app node scripts/init-ai-budget.mjs
```

Это отдельный ручной шаг, **не команда для каждого deploy**. Секреты не выводятся. Перед выполнением проверяют актуальный Compose и существующее состояние. Не запускайте `down -v`, не удаляйте volume/файл и не восстанавливайте более старый счётчик текущего дня для обхода бюджета.

## Как работает устойчивость

Все процессы одного хоста должны использовать **один физический файл на одном локальном томе**. Резервирование защищено эксклюзивным файловым lock, записью временного файла, fsync, atomic rename и fsync каталога. Состояние 0600, symlink/hardlink отвергаются. В файле нет IP, текстов диалога или секретов: только день, количество попыток и случайные идентификаторы временных слотов.

Слоты переживают рестарт и освобождаются после завершения/отмены запроса. После аварийного завершения процесса слот истекает через 120 секунд; это больше upstream-тайм-аута 45 секунд. Отмена HTTP-запроса не доказывает, что провайдер уже прекратил свою внутреннюю работу. Лимит параллельности относится к запросам приложения, а не к недоступной внутренней очереди провайдера.

Зависший `.lock` **не удаляется автоматически**. Для восстановления сначала остановите всех писателей этого проекта, сохраните и проверьте счётчик, затем устраните причину/оставшийся lock, сохранив дневное число. Счётчик, который не удалось надёжно восстановить, оставляйте закрытым до безопасного восстановления; не создавайте нулевой взамен в текущие сутки. Нужны доверенные стабильные системные часы: скачок вперёд способен ускорить истечение слотов, а откат относительно последней записи закрывает AI, пока время не станет согласованным. Статус /api/config кешируется до двух секунд; перед каждым upstream счётчик проверяется заново.

Несколько процессов/контейнеров одного хоста на общем томе покрыты тестами. Несколько хостов, независимые volumes, NFS и распределённые filesystem не поддерживаются: они могут умножить лимит. Для горизонтального масштабирования нужен централизованный атомарный бюджет (например, надёжно настроенный Redis/БД), не копии этого файла.

## Traefik, IP и заголовки

Приложение намеренно **не использует** `X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `X-Forwarded-Host` для лимита или установления доверия. Подмена этих заголовков не выдаёт новый бюджет. За Traefik действует честный общий входящий лимит; в несколько процессов он суммируется, но устойчивые ограничения 100/сутки и 2 слота остаются общими при одном файле.

Публичный режим требует HTTPS `PUBLIC_ORIGIN` без пути и завершающего слеша. POST без Origin либо с посторонним Origin отвергается. Дополнительные фронтенды разрешаются только точным HTTPS `CORS_ALLOWED_ORIGINS`. Серверный клиент способен подделать Origin: безопасность бюджета от этого не зависит. Не публикуйте host-порт backend в обход Traefik. На прокси дополнительно ограничьте скорость/размер запросов, допустимые Host, обеспечьте TLS и не логируйте тела или Authorization.

## Дополнительные модели

Администратор задаёт `AI_PROVIDERS_JSON`: `{id,label,baseUrl,model,apiKeyEnv}` и `AI_ALLOWED_HOSTS`: точные доверенные HTTPS-хосты. Значение ключа хранится отдельно в переменной с именем `apiKeyEnv`. Запрещены IP, localhost, пользовательские URL, credentials/query/fragment и перенаправления. Настройки браузера выбирают только готовые профили, не создают произвольный proxy. DNS доверенного хоста и запрет исходящего доступа во внутренние сети остаются ответственностью инфраструктуры.

## Контекст, приватность и ошибки

При подтверждённой отправке текст, история и выбранный контекст передаются провайдеру. Не отправляйте персональные данные, коммерческую тайну, пароли и ключи. Код доступа не уходит модели. История и код доступа хранятся только в памяти вкладки. «Очистить» удаляет локальную историю, но не уже переданные провайдеру данные.

Идентификаторы мер сервер разрешает через собственную библиотеку с метриками и ограничениями. Полные параметры калькулятора пересчитываются общей функцией; числовой ответ формирует приложение без обращения к модели. Денежные значения — млн ₽. AI может ошибаться и не заменяет экспертизу. Ответ отображается обычным текстом. Сервер не логирует запросы, ключи или подробные ошибки upstream.

## Однократная безопасная диагностика

Если прямой минимальный запрос работает, а свободный диалог сайта получает ошибку провайдера, выполните из корня обновлённого репозитория:

```sh
docker compose exec -T cost-reduction-app node --input-type=module < diagnose-ai.mjs
```

Скрипт поступает в stdin действующего контейнера; пересборка и перезапуск не нужны. Он импортирует **установленный в контейнере** `createApp`, запускает временный локальный обработчик только на `127.0.0.1` и использует его настоящую сборку запроса: Softline, `qwen3.8-27b-nvfp4`, системные инструкции приложения, пустой контекст, один нейтральный вопрос, temperature 0 и действующий серверный max_tokens (по умолчанию 1000). История посетителей не читается. Это не тест Traefik или браузера.

Выполняется **не более одного обращения к провайдеру**, без повторов и fallback. Если общие дневной лимит, параллельные слоты или конфигурация не разрешают запрос, обращений будет ноль. Общий устойчивый счётчик используется штатно; попытка, включая ошибку, расходует суточный лимит и может тарифицироваться. Работающий веб-процесс не перезапускается; минутный soft-limit временного обработчика отдельный, но жёсткие дневной лимит и слоты общие. Повторять тест без необходимости не следует.

Вывод — одна JSON-строка с `upstream_http`, `application_http`, `category`. Ключ, сообщения, ответ модели, заголовки и исходный текст ошибки никогда не выводятся. Категория берётся из закрытого списка; метки с `_hint` — лишь предположение по тексту ошибки, а не доказанная причина. `ok` означает, что приложение приняло полный ответ, а не только HTTP 200. При ошибке exit code равен 1. Не публикуйте `.env` или полный вывод `docker inspect`.


## Числовой результат и свободный диалог

Калькулятор и AI-обсуждение разделены. Полный набор пяти строго числовых полей возвращает серверный расчёт и снимок исходных данных, без обращения к модели. Неполные поля возвращают список недостающих значений; отсутствующее значение не считается нулём. Текст чата не изменяет подтверждённые поля. Расчёт доступен без AI-ключа, кода доступа и модельного бюджета, но с обычной проверкой Origin, размера запроса и частоты обращений. Статическая версия без API использует ту же детерминированную функцию локально.

Распознавание запросов о вычислениях в свободном тексте лишь направляет к форме и не извлекает числа или единицы. Оно не распознаёт все возможные формулировки. Произвольный AI-текст явно помечается непроверенным: гарантировать отсутствие неверной арифметики в нём нельзя. Для обещания «ни одного модельного финансового результата нигде» потребуется заменить произвольные ответы на выбор моделью разрешённых рекомендаций, текст которых задаёт сервер.

По умолчанию temperature=0 в интерфейсе, API и диагностике; шестерёнка разрешает явно выбрать другое значение. T=0 не является гарантией точности арифметики или полной повторяемости ответов.

Маршрутизация свободного текста не является смысловым классификатором: запрос с суммами прописью может не распознаться, а упоминание «не нужен расчёт» может открыть форму. Это навигационная подсказка, не гарантия. Запросы подтверждённого расчёта помечены calculationOnly и передают реальное согласие пользователя; при несовпадении версий клиент/сервер они завершаются безопасной ошибкой, а не переходят к модели.
